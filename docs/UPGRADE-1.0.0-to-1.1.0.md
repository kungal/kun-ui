# KunUI 升级指南:1.0.0 → 1.1.0

面向已在 **1.0.0** 的下游,升到 **1.1.0**。四个包(`@kungal/ui-core` / `ui-tokens` / `ui-vue` / `ui-nuxt`)始终**锁步同版本**,必须一起升。

```bash
pnpm up "@kungal/*@latest"   # → 1.1.0
```

> **进入 1.x 后遵循 [SemVer](https://semver.org/lang/zh-CN/)**:`minor`(1.0→1.1)与 `patch` 只做**向后兼容**的新增与修复,破坏性变更只会出现在下一个 `major`(2.0)。所以从 1.0 起,升级几乎都是「装上就好」——本篇只列**需要你回归或留意**的一处。
>
> 1.0.0 之前(0.5.2 → 1.0.0)的大跨度迁移见 [`UPGRADE-0.5.2-to-1.0.0.md`](./UPGRADE-0.5.2-to-1.0.0.md)。

---

## 1. ⚠️ 破坏性变更(必须处理)

**无。** 1.1.0 不含任何破坏性 API 变更:没有删除/重命名 props、事件或导出,旧代码无需改动即可工作。

---

## 2. 🎨 行为变化(升级后做一次回归)

不改 API,但交互会变,值得过一眼:

| 变化 | 版本 | 说明 |
|---|---|---|
| **`KunLightbox` 点击遮罩关闭** | 1.1.0 | 点击图片**四周的暗色遮罩**现在会关闭查看器,与现代图片查看器(PhotoSwipe、iOS 相册、GitHub 自带查看器等)一致,并与原有的 **Esc 关闭**互补。 |

要点:

- **只关在遮罩上**——点击图片本身、以及任意控件(缩放/旋转/下载/上一张/下一张/缩略图/关闭按钮)都**不会**关闭。
- **拖拽不会误关**:平移(放大后拖图)、滑动切图、双指缩放——这些手势收尾的那一次点击都被指针位移阈值挡掉,不会触发关闭。
- 关闭方式现共三种,行为一致:**点遮罩 / 按 Esc / 点右上角关闭按钮**,均触发既有的 `update:isOpen` → `false`(`v-model:is-open` 自动同步)。

**需要回归的情形(都很少见):**

- 你在 `KunLightbox` **外层自写过点击关闭逻辑**(比如给包裹层加了 backdrop click → 关闭):现在会**双重关闭**,可以把自写的那套删掉。
- 你**依赖了「点遮罩不关闭」**这一旧行为(例如把灯箱当常驻展示层):目前**没有关闭该行为的开关**,点遮罩一定会关。确有此需求请提 issue。

> 画廊模式(`KunLightboxGallery` + `KunLightboxGalleryItem`)与独立受控模式(`<KunLightbox v-model:is-open :images>`)都适用,无需改用法。

## 3. 📌 集成注意

本次**无新增集成步骤**。1.0.0 里的那几条(Tailwind `@source` 同时扫 ui-core 与 ui-vue、可选 base 层的 `prefers-reduced-motion`、库接管背景 `inert`、LCP 首图手动 `eager`、圆角 `--kun-radius-scale`)继续有效,详见 [`UPGRADE-0.5.2-to-1.0.0.md` §6](./UPGRADE-0.5.2-to-1.0.0.md#6-集成注意必读)。

---

## 4. ✅ 升级后自检清单

- [ ] `pnpm up "@kungal/*@latest"`,确认四个包都到 `1.1.0`(锁步同版本)。
- [ ] 用到 `KunLightbox` / 画廊的页面:确认点遮罩能关、点图片与控件不会关;拖拽/滑动切图不会误关。
- [ ] 若外层自写过遮罩点击关闭逻辑 —— 删掉,避免双重关闭。
