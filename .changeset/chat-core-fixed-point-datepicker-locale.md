`normalizeKunChatEntities` is now a fixed point, as its documentation says. Inline entities were cut at the boundaries of every blockquote, including a quote that nesting then dropped because it sat inside, or crossed, another quote. A second pass had no reason to keep that cut and merged the pieces back together. For example, `'中中b*bab'` with a spoiler across two nested quotes normalized to three spoiler runs, and normalizing that result gave two. Blockquotes are now settled among themselves first, and only a quote that survives cuts anything. Output changes only for input with overlapping blockquotes. The property test that should have caught this drew its cases from an LCG computed in doubles, which cycled after about 10,000 draws. It now uses mulberry32, runs 20,000 rounds, and fails on the old code.

`formatKunChatMarkdown` no longer loses text after a link or mention whose label ends on a line break. The parser checks for a `> ` quote prefix and the `\>` escape where the new line's text begins, which is after the label's closing `](…)`. The formatter decided whether to escape by reading the characters it had already written, and those end in `)` at that point. So `'a\n\\>b'` with a mention on the line break came back as `'a\n>b'`, and a `>` in that position was read as a quote marker and disappeared. The formatter now tracks the parser's line-start state. `parseKunChatMarkdown` is unchanged, so no composer input parses differently. Over 2.3 million random messages, `parse(format(m))` returned the text unchanged every time. The old code lost text in 50 of the first 300,000.

`KunDatePicker` formats the trigger text in its locale. A custom `format` with a month or weekday token showed English names in a zh-CN app. Measured with `format="yyyy MMMM do EEEE"`: the trigger now reads "2026 九月 27日 星期日" under zh-CN and "2026 September 27th Sunday" under en-US. The default numeric formats render as before.

`KunDatePicker` shows which cell the arrow keys are on. Focus stays on the trigger while the arrows move `aria-activedescendant`, so no cell ever matched `:focus-visible`, and a sighted keyboard user saw nothing move until the page turned. The active cell now draws the picker's focus ring once a key opens the panel or moves the cell, and drops it on a pointer press inside the panel. This follows React Aria's `useOption`, which shows a virtually focused option as focus-visible only under keyboard input. Opening the picker with a click shows no ring until an arrow key is pressed.
