# CLAUDE.md — kun-ui (KunUI design system)

## 铁律 (Iron Rules — non-negotiable; these override every other guideline in this file)

1. **This repo is upstream for the whole ecosystem.** Downstream repos (kungal forum, moyu/patch, letmoe, infra `apps/web`, …) carry the rule "never modify KunUI from a consumer repo — report bugs instead," so every report lands *here* and every change here ships to every consumer site. Additive first; treat an API change as a breaking-change review. When a downstream report arrives, judge honestly whether it is a library gap or a usage problem — both answers are common, and a wrong "fix" is paid for by every consumer.
2. **A push to `main` publishes to npm.** `release.yml` fires on every push to main: with any `.changeset/*.md` present it versions, commits the bump back to main, publishes all four packages under npm OIDC trusted publishing, and cuts a GitHub Release. So never push, merge a PR, or publish on your own initiative — do it when the user asks (their standing phrase is "提交并发布"). Never run `changeset publish` by hand and never hand-edit a version in `package.json`.
3. **No gradient backgrounds anywhere** — not in components, not in docs demos (`bg-gradient-*`, `from-*/via-*/to-*`, `linear-gradient()`, `radial-gradient()`, …). Solid semantic colors only; each has a 50–950 scale. Docs demos use realistic content — real images, `bg-content1`/bordered surfaces, actual KunUI components — never colored rectangles standing in for content.
4. **A new runtime dependency needs a capability argument, never a convenience one.** KunUI is headless, SSR-first, compositor-first. The deps it does carry are load-bearing infrastructure (`@floating-ui/vue`, `focus-trap`, `@vueuse/core`, `date-fns`, `thumbhash`, `vue-advanced-cropper`, `clsx` + `tailwind-merge` in ui-core). For a *presentation* concern the default answer to "should KunUI use library X" is **no** — solve it with CSS or a native API. The standing example: overlayscrollbars was rejected for KunScrollShadow (~35 KB of runtime that wraps the scroller in its own DOM and runs JS per scroll) in favour of a pure-CSS `scrollbar="thin"`, accepting the one thing CSS cannot do (auto-hiding overlay bars). A downstream *app* may take such a dependency locally; the library may not.
5. **A correctness-critical CSS declaration is an inline `:style`, never a utility class.** `dist/style.css` ships only component-scoped CSS — every Tailwind utility is regenerated by the **consumer's** Tailwind scanning our compiled `dist/index.js` via `@source`. A class can be missed or purged by a consumer's pipeline; an inline style cannot. Classes are for appearance, inline styles for correctness. Corollary: any class string you do write must survive into `dist/index.js` — check it there, not in the source.

## What this repo is

KunUI, the shared cross-framework component library for the NextMoe/KunGal ecosystem: one design language, multiple render layers. pnpm workspace, 4 packages versioned in lockstep (currently 2.22.x), released via changesets.

- `@kungal/ui-tokens` — framework-agnostic Tailwind v4 theme (semantic colors, radius, OKLCH palette). `gen:tokens` asserts every solid/on-color pair clears WCAG AA in both modes and exits non-zero if one doesn't.
- `@kungal/ui-core` — design types, `cn()`, variant matrix, radius system, the 29 inlined icons.
- `@kungal/ui-vue` — the Vue 3 layer, Nuxt-decoupled: 71 SFCs, 70 registered in `KUN_COMPONENT_NAMES`, plus 22 exported composables.
- `@kungal/ui-nuxt` — Nuxt layer wrapping ui-vue (auto-imports, injection). Ships `nuxt.config.ts` + `app/` as *source*: no build, no typecheck of its own — building `apps/docs` is the only thing that exercises it.

React (`@kungal/ui-react`) is a planned future layer — `docs/architecture.md` carries the honest constraint analysis (no technology runs `.vue` inside React) and the phased roadmap.

Apps: `apps/docs` (the Nuxt docs site, also the release-verification surface), `apps/playground` (Vite), `apps/nuxt-playground`. All three are in the changesets `ignore` list.

## Commands

```bash
pnpm install
pnpm build                 # all packages (this must precede any typecheck on a bare checkout)
pnpm typecheck             # packages
pnpm typecheck:apps        # ./apps/* — only apps/playground defines the script today
pnpm build:docs
pnpm gen                   # ALL generators, in dependency order — run after any component change
pnpm changeset             # record a changeset for the release train
```

`pnpm gen` = `gen:tokens` → `gen:icons` → `gen:meta` → `gen:page-md` → `gen:changelog` → `gen:upgrade` → `gen:llms`. The package generators run first because they write into `packages/*/src`, which the docs generators then read.

## The release train

`.changeset/*.md` → commit → push `main` → `release.yml`: `changeset version`, `gen:changelog`, commit `ci: release packages [skip ci]` back to main, `ci:publish` (build + `changeset publish`, OIDC + provenance), push tags, create the GitHub Release from the newest CHANGELOG block, dispatch `docs-image`.

- **No changesets on the push → the workflow bails out early and publishes nothing.** Harmless, cheap.
- The `fixed` group versions all four `@kungal/*` together, so one `'@kungal/ui-vue': minor` changeset bumps all four.
- The changeset body *is* the release note and the docs `/changelog` entry. Write it for a consumer: what changed, what it costs them, why the design is what it is.
- A `docs-image` run showing **cancelled** on the feature commit is expected, not a failure — the `[skip ci]` bump commit supersedes it under the workflow's concurrency group and a fresh run starts on the bump.
- Verify a release from npm, not from a green check: `npm pack @kungal/ui-vue@<v>` and grep `dist/index.js` for the new symbols and class strings.

**PRs.** `check.yml` gates every PR. For a stacked PR, merge the base with a **merge commit** — squash or rebase rewrites the base's SHA, breaks the stacked branch's ancestry and manufactures conflicts in exactly the files both PRs touched. Rebase the upper branch onto the released `main` and let CI re-run before merging it: its green check was against the pre-release base.

## The CI gate, and the traps it encodes

`check.yml` has two jobs; both exist because each trap below actually shipped once.

**Typecheck and build** — `pnpm build` → `typecheck` → `typecheck:apps` → `build:docs`.
- Build **first**: every internal dep is `workspace:*` and resolves to the dependency's `dist`, *including for type resolution*. `pnpm typecheck` on a bare checkout fails with `Cannot find module '@kungal/ui-core'`. You never see this locally, where `dist` is lying around from the last build.
- `typecheck` is not redundant with the build's vue-tsc pass: that one runs `tsconfig.build.json` (src only), this one covers `tsconfig.json` (src + `vite.config.ts`) and gives ui-core a real `tsc --noEmit`, which its tsup `dts: true` is not.

**Generated files are up to date** — builds ui-core, runs `pnpm gen`, fails on any `git status --porcelain` output.
- `--porcelain`, not `git diff --exit-code`: a generator producing a brand-new file leaves it *untracked*, which a diff cannot see. That is how 15 component pages stayed missing.
- Missing `dist/index.d.ts` does **not** fail TypeScript — it silently widens every unresolvable type to `any`, exit code 0. That once turned 83 prop types across 36 pages into `"any"`. `gen-meta.mjs` now refuses to run in that state; the job builds ui-core to keep it from having to.
- **JSDoc (`/** */`) surfaces in the docs PropsTable; `//` does not.** A prop's default comes from `withDefaults`, or from a JSDoc `@default` tag when the real default is conditional. So: every public prop gets JSDoc, and editing a `//` comment does not require regenerating.
- `vue-component-meta` reports an *uninstantiated* generic SFC (`items: T[]` → the literal `"T[]"`); `gen-meta.mjs` reads the SFC's `generic="T extends C = D"` and substitutes `D`, fixpoint-style, because a later parameter's default can name an earlier one.

## Comments

**Default: none.** Code that can be read gets no comment. A comment is earned by a mistake that already happened — an agent or a person got it wrong, a review caught it, a browser did something undocumented — and it records the wrong conclusion so the next reader does not reach it again. If you cannot name the incident, there is no comment to write. Write the conclusion, not the mechanism.

Two obligations specific to this repo, where the comment is a record rather than a warning:

- **Every public prop gets a JSDoc block** — it is not a comment, it is the docs. It appears verbatim in the PropsTable and in `llms.txt`.
- **A constraint that is true but invisible from the file**: a spec rule, a browser bug, a required ordering, a measured platform fact. These components are made of them — `overflow: hidden` not stopping touch scroll on iOS; scrollbar width having to be measured *before* `overflow: hidden`; `dvh` ignoring the virtual keyboard; `touch-action` resolving up to the first scrolling ancestor. A reader who does not know one of these will "simplify" it away. Quote real output or the spec verbatim when it is the point.

English, and short. Never write restatements, section banners, or `TODO` without an owner. Machine-semantic directives (`@ts-expect-error`, `eslint-disable`, `// AUTO-GENERATED … do not edit`) are not comments and are never removed.

## Conventions

- **Path-scoped commits** (`git commit -- <paths>`), never `add -A`. Note everything after `--` is a path, so a message must come from `-F <file>` or precede the `--`. English-only commit messages and comments.
- All frontend functions are arrow functions; compose classes with `cn()`.
- A new component must be added to `KUN_COMPONENT_NAMES` (`packages/vue/src/componentNames.ts`) — the single source the Nuxt layer auto-registers from, and typed against `Record<KunComponentName, Component>` in `index.ts`, which fails typecheck if you forget.
- Icons are **bundled, never fetched**: only the 29 names in `WANT` in `packages/ui-core/scripts/gen-icons.mjs` exist. Using an unbundled name renders nothing. Add it there and run `pnpm gen:icons`. (`apps/docs` registers ~15 extra ones for its own pages — those are not available to consumers.)
- Responsive behaviour is **Tailwind breakpoint classes, never `useMediaQuery`**: VueUse media queries evaluate `false` on the server unless the app calls `provideSSRWidth`, so a JS-driven variant SSRs the wrong layout and snaps on hydration. A JS media query is acceptable only to gate a *gesture or listener*, never to choose markup or geometry.
- Dev-only warnings use `process.env.NODE_ENV !== 'production'`, **not `import.meta.env.DEV`** — Vite folds the latter to `false` when it builds this package, so the warning is stripped from the published bundle and is dead code that reads as live.
- A Boolean prop that must distinguish unset from `false` needs `withDefaults(..., { x: undefined })`; an absent Boolean prop otherwise casts to `false`.

## Component contracts (do not break)

- **KunModal owns its width via the `size` prop** (default `md` = 28rem); consumers must not wrap fixed-width divs in the slot.
- **Closing animations require the component to stay mounted** — consumers bind `v-model`, not `v-if`. Keep that working.
- **Overlays stack via `z-index` and `Teleport to="body"`, not the top layer.** Native `<dialog showModal()>` is deliberately *not* used: proven in Chrome 151, an element in the top layer paints above `z-index: 2147483647` and everything outside its subtree becomes inert — eleven components teleport to `body`, so they would go dead inside a modal. Escape / close requests are answered by the topmost overlay only (`useKunOverlayZIndex`).
- **SSR: module-scoped mutable state is shared across requests.** `useKunMessage`'s module-level `ref([])` once accumulated 492 toasts across SSR requests and baked them into every page's HTML. Module scope is right for a refcount or a stack (`useBodyScrollLock`, `useKunOverlayZIndex`); it is wrong for anything user-visible unless the server path is a no-op and the provider is client-only.
- **DOM-measured values are client-only**; prop-derived values are server-safe. When a measured value has a visual default, ship it as an inline style so it survives into the SSR HTML.

## Verifying work

There is **no test runner in this repo.** Verification is (a) the CI gate and (b) measuring the real thing in a real browser — Playwright/CDP against `apps/docs` or `apps/playground`, or a purpose-built harness page. State what was measured and what the numbers were; do not report a behaviour you reasoned about as if you had observed it. When a claim turns out to be wrong, retract it explicitly.

Recurring traps in that loop:

- `pkill -f <pattern>` inside a compound command matches the invoking shell and kills it (exit 144), silently aborting the rest of the chain. Find the pid with `ss -ltnp` and `kill` it.
- Playwright blocks the `file:` protocol — serve harnesses over `python3 -m http.server`.
- Playwright screenshots can land in the repo root instead of the reported path; `.playwright-mcp/` is gitignored, so write there, and `fd` any strays before committing.
- The Bash tool's cwd persists between calls — a `cd apps/docs` breaks every later relative path. Use absolute paths.
- Real CDP touch events cost ~44 ms each, capping synthetic gesture velocity at ~0.34 px/ms; use in-page synthetic `TouchEvent`s for velocity-sensitive tests and keep real touch for the ones that need native scrolling.
- Before assuming a dev server is yours, check — port 5199 belongs to another project on this machine.

## What the user expects

- **Research before design.** "搜索一下现代 UI 组件库的最佳实践" is the standing request: read Radix / Base UI / HeroUI / Reka / vaul / Vant *source and docs* — via `gh api` or the raw file, not from memory — and say what you actually read. Cite constants and quotes; note where we deliberately diverge and why.
- **Animation must feel physical, not snappy.** An aggressive emphasized ease-out reads as "snap, then freeze"; the fix that satisfied them was a sampled ballistic trajectory baked into ~16 linear keyframes, gravity as t² acceleration, gentle launch. Prefer sampling a real curve over one fat bezier; stay compositor-only (transform/opacity); honour `prefers-reduced-motion`.
- Iterating on motion and layout by eye is normal here — expect several rounds of "再小一点" on a demo the user is watching. Land the change, tell them what to look at, and do not publish until they say so.
